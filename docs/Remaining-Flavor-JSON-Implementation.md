# Remaining flavor-message extraction

Implemented October 31, 2026 after approval of the research preflight. Repository build only; installation and live-game acceptance remain separate.

All 26 audited HUD messages now use FlavorNotifications.json and MMEFlavorText.psc. The original notification expression remains inline as an already-rendered compiled fallback at every call site. Comparing the ten source files against their pre-implementation snapshots confirmed that only those 26 expressions changed. Triggers, existing player/NPC branches, notification toggles, success/rejection paths, counts, deadlines, state writes, framework operations, sounds and narration calls were retained.

The initial file has one existing-wording variant per pool. The facade avoids random selection for a single personal or ordinary-base variant, then delegates multi-variant/legacy/invalid-file handling to the existing MMETextPool reader. It validates the route's supplied required tokens and rejects unknown, missing or malformed braces before calling the existing single-pass renderer. Replacement actor/armor/item names are never parsed as templates. Blank/invalid output falls back to the original rendered string without interrupting the action. Existing deduplicated source traces and rate-limited text-pool failures identify the entry, subject and reason; no polling, new gameplay settings or additional player-facing diagnostics were added.

Explicit contracts in tools/flavor-notification-schema.json keep required dynamic facts independent of editable prose. The existing catalog generator embeds these 26 pools and their presentation metadata, producing 173 entries overall: 51 AI controls, 86 game-message controls, and 36 retained internal entries. All original 147 IDs, paths, defaults and token contracts remain unchanged.

Game Messages & Stories exposes nine additions normally. Show minor messages reveals 17 additional equipment, rescue, encounter, conversion-confirmation and level-reduction entries. The checkbox changes only the editor list and is remembered in the existing local navigation preference when available. A count identifies hidden minor customizations. Minor entries remain player-editable metadata, not internal fields: filtering retains drafts, Save includes staged edits, and Reset Player Text explicitly includes minor entries hidden by filters while retaining internal/unknown customizations. No duplicate editor or new MCM control was introduced.

Coverage executes the actual Papyrus facade, selection function and renderer against mocked native boundaries for one/multiple/personal/base values, missing/malformed/wrong-type pools, blanks, invalid placeholders, numeric contracts, actor context and literal braces in replacement values. Inventory checks bind all 26 original expressions and unchanged shipped defaults. Actual dashboard tests cover 69 normal/86 expanded messages, preference restoration, hidden drafts and reset. Existing native store tests validate all 173 defaults and metadata through the real bounded transport and profile transaction workflows. Source/compile tests complement these checks; they do not establish engine-side notification timing or visual acceptance.

The package pipeline compiles the common helper and affected scripts, regenerates backend variants, ships the new JSON, rebuilds standard/OStim outputs and verifies their source/PEX and manifests. The catalog requires universal/VR DLL rebuilds. Final build/archive results are recorded in the task response. No original MME/third-party source override was added, and README, installed MO2/Vortex files, profiles and live game state were not changed by this task.
