# Individual armor fittings

Vendor and ordinary-item armor-management services now modify one worn body item: Milking (class 1), Living (2), Tentacle/old Parasite (3), and Dwemer (4). The labels are `(Milking)`, `(Living)`, `(Tentacle)` and `(Dwemer)`. The engine inventory identity, not the label or armor base/name, owns the fitting. A copy can carry only one class. Ambiguous worn stacks fail closed.

## Existing saves
A new game is not an intended requirement. Back up the paired `.ess` and `.skse` files before upgrading. Unequip previously managed ordinary clothing (including affected companions), use original MME Armor Support ERASE LIST for the three old lists, install the update, and refit the individual copies you want. Do not reset Milk Maids or the entire mod. Old names cannot prove which physical copy received a vendor service, so they are never automatically converted. The old lists are retained for inspection/clearing and are dormant for ordinary fitting gameplay. A one-time notice appears when nonempty legacy lists are observed. The original ERASE LIST and purge spell clear legacy arrays only; they do not remove new physical-item fittings. Use the corresponding service/current worn-item control to remove those.

Original MCM Add/Remove acts on the player's worn body item and selected class. Its numbered legacy slots are read-only. Armor-management spells act on the target's worn body item. Vendor eligibility is preserved. Removing/refitting revalidates the captured physical identity, not just the base form. Existing Dwemer records, serials, name ownership and fit levels migrate automatically: version-three records accept version-one and version-two layouts, treating them as class 4. Do not downgrade the DLL against a newly saved co-save; restore the pre-upgrade pair for rollback.

Dedicated suits and explicit JSON/exact-form compatibility remain intrinsic definitions. Those definitions may intentionally affect all copies. They are not ordinary vendor fittings and are protected from being overwritten. OG name rules for supported special suits remain in place. Existing explicit name/form API registrations remain compatibility definitions; they do not claim to target an inventory instance.

## Effects and framework boundaries
MME remains the authority for Milk Maid slots, milk calculations, Lactacid and inventory output. Production, milking-mode and SexLab event paths use a cached, non-latent actor/item class query. Equip effects remain in the existing compatibility owner. Player conversion follows established MME functions; equipping a fitting cannot automatically convert an ordinary NPC. Living/Tentacle passive ownership is tracked per actor and reconciled against currently recognized worn equipment on startup/observation and unequip, retaining the passive when another supported Living item is still worn. Migration reconciles an old MME armor passive with no remaining recognized worn support. It does not undo historical breast-row changes, Milk Maid conversion or progression.

The existing refit rules still exclude Living/Tentacle equipment; ordinary Milking and supported Dwemer paths retain their guards. A physical fitting's stored fit level follows the item, and an instance refit targets the worn item. Familiarity uses the stable item serial for all fitted classes. Master-off stops fitting operations and reconciles extension-owned passives through the existing controller path; static original armor behavior remains original MME's responsibility.

All new inventory/name mutations stay in game-thread native transactions. No new polling timer or inventory-wide scan is added. Name restoration remains ownership checked: preserve subsequent player renames, quest/alias names, enchantments, tempering, item count and engine UID. Two fitted items with the same display name can still group in a UI; names are not identity.

## Diagnostics and acceptance
`[MME Item Attachments]` master-gated traces report actor, class, item identity, operation/result, label and effect cleanup. Existing `[MME Dwemer Instance]` Papyrus wrappers remain valid for callers of the older facade. Genuine invalid records, native transaction failures and failed passive cleanup alarm independently of the master toggle with deduplication. Disabled features, protected suits, class conflicts and item changes are expected skips.

Required validation includes same-base spare isolation for all classes, player/NPC targets, transfer/container/drop, save/load and old Dwemer migration, class conflicts, first/repeated stories, master/optional dependency behavior, refit and removal/name restoration, Living/Tentacle cleanup, ordinary MCM/spell services and legacy reset. Automated state/facade tests and compilation do not prove live acceptance. Standard, P+ hook, OStim-only and Estrus Unified variants must all ship matching source/PEX pairs. Live acceptance is pending for the new classes.
